# Blink Link — 안드로이드 무선 연결 복구

사용자의 S23 Ultra / One UI 8.5 / Android 16용으로 만든 개인용 앱이다. 등록한 Wi-Fi에서 무선 디버깅을 다시 켜 PC의 scrcpy가 연결할 수 있도록 준비한다. Android 16 AOSP 가상 기기에서 검증하며, 삼성 실물 기기 검증은 별도로 남긴다.

- 소스: `C:\ai\projects\scrcpy-gui\android`
- APK: `C:\ai\projects\scrcpy-gui\app\android\BlinkLink-0.3.0-debug.apk`
- 앱 ID: `kr.blinklabs.blinklink`
- 실행 기록: `C:\ai\projects\scrcpy-gui\work\android-lab`

## 매크로

0.3.0부터 **내 매크로 열기**에서 실행 조건과 추가 조건, 순서 있는 동작을 직접 구성한다. 충전·시간·Wi-Fi·화면 이벤트, 알림·읽기·대기·앱 열기 알림·미디어 음량·진동·디버깅 복구를 지원한다. 편집·복제·개별 허용·JSON 가져오기/내보내기와 실행 기록을 제공한다. 자세한 동작·제한·검사는 [매크로 안내](MACROS.md)를 참조한다.

## 기능

등록한 Wi-Fi에서 무선 디버깅 꺼짐을 감지해 복구한다. Wi-Fi 재연결, 재부팅 후 첫 잠금 해제, 앱 업데이트 이후에도 사용자가 시작한 감시를 재개한다. 큰 버튼으로 한 번 복구, 자동 복구 일시정지, 디버깅 끄기를 제공한다. 알림의 일시정지와 빠른 설정 타일의 앱 열기를 지원한다.

Wi-Fi 이름이 확인되지 않거나 등록 이름과 다르면 자동으로 켜지 않는다. 기존 디버깅을 누가 켰는지는 Android 설정값만으로 판별할 수 없으므로, 다른 Wi-Fi로 이동하더라도 이 앱이 자동으로 끄지는 않는다. 끄려면 **디버깅 끄고 복구 정지**를 명시적으로 선택한다. 이름 비교는 SSID 기준이며 같은 이름의 위조 네트워크를 식별하지 못한다. Android 자체 네트워크 허용과 PC 페어링은 유지한다.

화면과 빠른 설정 타일은 실제 서비스 실행 상태를 표시한다. Android에서 앱을 강제 중지한 뒤 다시 열면 **감시 다시 시작**을 눌러야 한다. 사용자 중지 이후 다시 전달되는 부팅 알림만으로 감시를 재시작하지 않는다.

안구마우스 사용과 반복 입력 부담은 `ik` 자료에서 확인했다. 사용자의 MacroDroid 매크로 내보내기 파일은 없으므로 다른 생활 자동화 기능을 이미 사용 중인 것으로 간주하지 않았다. 광고·결제·계정·외부 서버·인터넷 권한은 없다. Wi-Fi 이름과 최대 약 6,000자의 동작 기록을 앱 내부에 저장한다.

## 휴대폰 설치 및 최초 준비

0.2.0은 **연결 / 설정 / 기록** 화면으로 나눈다. 연결에서 상태 확인·한 번 복구·자동 복구를 조작하고, 설정에서 세 단계의 준비 상태와 펼쳐 보는 권한 안내를 확인한다. 기록은 별도 화면에서 선택하거나 복사한다. 큰 버튼, 시스템 다크 테마, 글자 확대와 가로 화면을 지원한다.

1. PC의 scrcpy-gui에서 휴대폰과 한 번 무선 페어링한다. 휴대폰 개발자 옵션 → 무선 디버깅 → 페어링 코드로 기기 페어링을 사용한다.
2. APK를 설치한다. PC에서 할 경우 `android\install.ps1 -Serial '실제기기주소:포트' -GrantPermission`을 실행한다. 스크립트는 지정 기기에 설치하고 명시한 스위치가 있을 때만 `WRITE_SECURE_SETTINGS`를 부여한다. 실물 기기에 대한 이 명령은 이번 개발 중 실행하지 않았다.
3. Blink Link의 **설정 → 권한 설정 방법**에서 정확한 위치·알림 권한을 허용한다. 앱 권한의 위치를 **항상 허용**으로 정하고 Android 위치를 켠다. 이는 백그라운드에서 Wi-Fi 이름을 읽기 위한 조건이다. 위치 좌표를 수집하지 않는다.
4. 설정에서 **현재 Wi-Fi 등록** 후 **연결** 화면의 **자동 복구 시작**을 누른다. Android의 무선 디버깅 허용 창에서 본인의 네트워크를 확인하고 **이 네트워크에서 항상 허용**을 선택한다. 재부팅 이후 네트워크 신뢰가 유지되는지는 삼성 실기에서 확인해야 한다.
5. PC scrcpy-gui에서 기기를 찾고 연결한다. 앱의 '무선 디버깅 켜짐'은 PC 미러링 연결 성공과 다르다.

휴대폰의 앱 배터리 설정을 '제한 없음'으로 설정하면 제조사에 의한 감시 종료를 줄일 수 있다. 설정 변경은 사용자가 직접 선택한다. 최초 준비 이후에도 PIN 잠금 해제나 시스템 허용 창이 필요한 경우가 있으며, 이를 자동으로 승인하지 않는다.

## 한계

- S23 Ultra / One UI 8.5에서 설치, 권한, 네트워크 신뢰 유지, 절전, 실제 scrcpy 연결은 아직 확인하지 않았다.
- 재부팅 후 최초 잠금 해제 전에는 감시를 시작하지 않는다. 강제 중지, Android의 활성 앱 중지, 권한 취소, 배터리 제한으로 감시가 중단될 수 있다.
- 30초 점검과 설정/네트워크 콜백을 사용한다. CPU를 계속 깨우지 않으므로 깊은 절전에서 즉시 복구를 보장하지 않는다.
- Android 설정 요청은 거절될 수 있다. 자동 켜기 요청은 성공 여부와 무관하게 **최근 5분에 최대 3회**, 요청 사이 최소 5초로 제한한다. 횟수는 서비스·앱 프로세스 재시작에도 유지하며 새 기기 부팅에서는 초기화한다. 대기 중에도 **지금 한 번 복구**는 사용자의 명시적 요청으로 실행할 수 있다.
- PC 앱 자동 실행이나 scrcpy 프로세스 재시작은 이 Android 앱의 기능이 아니다. 현재 PC 앱의 연결 탐색 기능과 함께 사용한다.
- MacroDroid 전체 기능·사용자 매크로 가져오기·유료 제한 변경은 구현하지 않았다. 필요한 Android API 동작을 독립적으로 구현했다.
- APK는 개발용 키로 서명한 개인 시험 버전이다. 키는 Git 제외 `work\android-lab\blinklink-debug.jks`에 보존한다. 삭제하거나 바꾸면 기존 설치에 덮어쓸 수 없다.

## 빌드 및 검사

Java 17, Android platform 36, build-tools 36.0.0으로 `android\build.ps1`을 실행한다. 기본 도구 경로는 `work\android-lab\jdk`, `work\android-lab\sdk`이며 `-JavaHome`, `-Sdk`로 지정할 수 있다. Gradle이나 외부 앱 라이브러리를 사용하지 않는다. `javac → D8 → aapt2 → zipalign → apksigner`로 APK를 생성하고 정책 검사 10건, 재시도 예산 검사 14건, APK 서명 검증을 실행한다. 매번 새 `android\build\run-<ID>`를 사용해 삭제된 클래스가 섞이지 않도록 한다. 외부 SDK를 지정한 새 체크아웃에서도 서명 키의 부모 폴더를 생성한다.
