# Blink Link — 안드로이드 무선 연결 복구

사용자의 S23 Ultra / One UI 8.5 / Android 16용으로 만든 개인용 앱이다. 등록한 Wi-Fi에서 무선 디버깅을 다시 켜 PC의 scrcpy가 연결할 수 있도록 준비한다. Android 16 AOSP 가상 기기에서 검증하며, 삼성 실물 기기 검증은 별도로 남긴다.

- 소스: `C:\ai\projects\scrcpy-gui\android`
- APK: `C:\ai\projects\scrcpy-gui\app\android\BlinkLink-0.1.0-debug.apk`
- 앱 ID: `kr.blinklabs.blinklink`
- 실행 기록: `C:\ai\projects\scrcpy-gui\work\android-lab`

## 기능

등록한 Wi-Fi에서 무선 디버깅 꺼짐을 감지해 복구한다. Wi-Fi 재연결, 재부팅 후 첫 잠금 해제, 앱 업데이트 이후에도 사용자가 시작한 감시를 재개한다. 큰 버튼으로 한 번 복구, 자동 복구 일시정지, 디버깅 끄기를 제공한다. 알림의 일시정지와 빠른 설정 타일의 앱 열기를 지원한다.

Wi-Fi 이름이 확인되지 않거나 등록 이름과 다르면 자동으로 켜지 않는다. 다른 Wi-Fi로 바뀌면 이 앱이 켰던 디버깅에 대해 끄기를 요청한다. 이름 비교는 SSID 기준이며 같은 이름의 위조 네트워크를 식별하지 못한다. Android 자체 네트워크 허용과 PC 페어링은 유지한다.

안구마우스 사용과 반복 입력 부담은 `ik` 자료에서 확인했다. 사용자의 MacroDroid 매크로 내보내기 파일은 없으므로 다른 생활 자동화 기능을 이미 사용 중인 것으로 간주하지 않았다. 광고·결제·계정·외부 서버·인터넷 권한은 없다. Wi-Fi 이름과 최대 약 6,000자의 동작 기록을 앱 내부에 저장한다.

## 휴대폰 설치 및 최초 준비

1. PC의 scrcpy-gui에서 휴대폰과 한 번 무선 페어링한다. 휴대폰 개발자 옵션 → 무선 디버깅 → 페어링 코드로 기기 페어링을 사용한다.
2. APK를 설치한다. PC에서 할 경우 `android\install.ps1 -Serial '실제기기주소:포트' -GrantPermission`을 실행한다. 스크립트는 지정 기기에 설치하고 명시한 스위치가 있을 때만 `WRITE_SECURE_SETTINGS`를 부여한다. 실물 기기에 대한 이 명령은 이번 개발 중 실행하지 않았다.
3. Blink Link에서 정확한 위치·알림 권한을 허용한다. 앱 권한의 위치를 **항상 허용**으로 정하고 Android 위치를 켠다. 이는 백그라운드에서 Wi-Fi 이름을 읽기 위한 조건이다. 위치 좌표를 수집하지 않는다.
4. **현재 Wi-Fi 등록** 후 **자동 복구 시작**을 누른다. Android의 무선 디버깅 허용 창에서 본인의 네트워크를 확인하고 **이 네트워크에서 항상 허용**을 선택한다. 재부팅 이후 네트워크 신뢰가 유지되는지는 삼성 실기에서 확인해야 한다.
5. PC scrcpy-gui에서 기기를 찾고 연결한다. 앱의 '무선 디버깅 켜짐'은 PC 미러링 연결 성공과 다르다.

휴대폰의 앱 배터리 설정을 '제한 없음'으로 설정하면 제조사에 의한 감시 종료를 줄일 수 있다. 설정 변경은 사용자가 직접 선택한다. 최초 준비 이후에도 PIN 잠금 해제나 시스템 허용 창이 필요한 경우가 있으며, 이를 자동으로 승인하지 않는다.

## 한계

- S23 Ultra / One UI 8.5에서 설치, 권한, 네트워크 신뢰 유지, 절전, 실제 scrcpy 연결은 아직 확인하지 않았다.
- 재부팅 후 최초 잠금 해제 전에는 감시를 시작하지 않는다. 강제 중지, Android의 활성 앱 중지, 권한 취소, 배터리 제한으로 감시가 중단될 수 있다.
- 30초 점검과 설정/네트워크 콜백을 사용한다. CPU를 계속 깨우지 않으므로 깊은 절전에서 즉시 복구를 보장하지 않는다.
- Android 설정 요청은 거절될 수 있다. 결과를 다시 읽어 표시하고 실패 시 5분 구간에 최대 3회 요청한다. 성공하면 실패 횟수를 초기화한다.
- PC 앱 자동 실행이나 scrcpy 프로세스 재시작은 이 Android 앱의 기능이 아니다. 현재 PC 앱의 연결 탐색 기능과 함께 사용한다.
- MacroDroid 전체 기능·사용자 매크로 가져오기·유료 제한 변경은 구현하지 않았다. 필요한 Android API 동작을 독립적으로 구현했다.
- APK는 개발용 키로 서명한 개인 시험 버전이다. 키는 Git 제외 `work\android-lab\blinklink-debug.jks`에 보존한다. 삭제하거나 바꾸면 기존 설치에 덮어쓸 수 없다.

## 빌드 및 검사

Java 17, Android platform 36, build-tools 36.0.0으로 `android\build.ps1`을 실행한다. 기본 도구 경로는 `work\android-lab\jdk`, `work\android-lab\sdk`이며 `-JavaHome`, `-Sdk`로 지정할 수 있다. Gradle이나 외부 앱 라이브러리를 사용하지 않는다. `javac → D8 → aapt2 → zipalign → apksigner`로 APK를 생성하고 정책 검사 10건과 APK 서명 검증을 실행한다.

실행 검사와 원본 분석의 범위는 [검증 기록](VALIDATION-2026-11-11.md)을 참조한다. SDK·가상 디스크·제3자 APK·디컴파일 자료는 Git에 넣지 않는다.
