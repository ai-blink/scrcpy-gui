# Blink Link 0.2.0 UI/UX 개선

2026-11-11. 대상은 Android companion 앱이며 PC WPF 화면 변경은 이 작업에 포함하지 않았다.

## 변경

- 길게 이어지던 단일 화면을 연결·설정·기록으로 분리했다. 주요 두 조작은 연결 화면에서 스크롤 없이 보이고, 하단 탐색은 고정된다.
- 최초 준비를 Wi-Fi 확인 권한 / 사용할 Wi-Fi / PC 연결 권한의 세 단계로 표시한다. 준비된 권한의 긴 설명은 접고 필요할 때 펼친다.
- 복사와 오류 안내를 하단 탐색 위에 표시하고 접근성 권장 표시 시간을 적용했다. 기록 선택 중에는 내용 갱신을 멈춘다.
- 주요 버튼 최소 64dp, 탐색 버튼 최소 56dp, 명확한 포커스·호버·눌림 상태를 적용했다. 다크 테마, 시스템 글자 크기, 화면 회전과 시스템 뒤로 가기를 지원한다.
- 백그라운드 위치 권한이 없어도 전경에서 Wi-Fi 확인과 PC 권한 조건을 충족하면 한 번 복구할 수 있다. 자동 감시는 전체 준비 조건을 요구한다.
- 자동 감시·재시도 제한·사용자 중지 처리 엔진은 변경하지 않았다.

화면 기준과 색상은 [DESIGN.md](DESIGN.md), 설치는 [README.md](README.md)를 참조한다.

## 화면 검증

실행: `python android/tests/emulator_ui.py`. 전용 Android 16 AVD `BlinkLink16` / `emulator-5580`만 사용한다. 매 ADB 조작 전 AVD 이름·qemu 속성·패키지를 확인한다. 창 없는 실행으로 호스트 키보드·마우스·포커스에 입력하지 않는다. 테스트 종료 시 게스트 테마·글자 크기·회전 설정을 복원한다.

실행 결과와 실제 렌더링 화면: `work/android-lab/ui-020/results.json`, 같은 폴더의 PNG·XML·`crash-log.txt`.

최종 APK에서 아래 10개 UI 시나리오가 모두 통과했다. 게스트 표시 설정 복원값이 원래 값과 일치했고 crash 버퍼에 앱 충돌은 없었다. 미리보기는 `app/android/BlinkLink-0.2.0-preview.png`와 `BlinkLink-0.2.0-dark-preview.png`에 저장했다.

검증 항목: 홈 주요 동작과 터치 영역, 일시정지/한 번 복구, 단계별 준비 상태/PC 안내/복사 피드백, 기록/뒤로 가기, 강제 중지 후 재개, 다크 테마, 130% 글자 크기, 가로 전환과 탭 유지, 백그라운드 위치 권한 없는 수동 복구, PC 권한 누락 시 설정 경로.

고정 색상 12쌍의 대비 계산에서 본문·버튼·선택 상태·성공/주의/종료 글자의 대비는 모두 4.5:1 이상이었다(최소 5.84:1). `contrast.json`에 수치를 보관한다. Impeccable detector 결과는 `[]`였지만 Java 네이티브 UI에 대한 검증 범위가 명확하지 않아 접근성 합격 근거로 사용하지 않았다. 실제 PNG와 Android UI XML을 함께 확인했다.
