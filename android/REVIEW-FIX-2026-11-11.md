# Blink Link 0.1.1 — 리뷰 수정 기록

대상은 0.1.0 리뷰의 결함 6건과 보완 사항 2건이다. 사용자 승인 후 소스와 시험 코드를 수정했다. 제품 출력은 `C:\ai\projects\scrcpy-gui\app\android\BlinkLink-0.1.1-debug.apk`, 개발용 서명 키는 0.1.0과 같다. 물리 휴대폰에는 설치하거나 설정을 변경하지 않았다.

## 수정

| 리뷰 문제 | 0.1.1 변경 |
|---|---|
| 서비스가 없어도 사용 중 표시 | 사용자 설정 `enabled`와 현재 프로세스의 서비스 실행 상태를 분리. 중단 시 `감시 다시 시작` 버튼 제공. 타일도 실제 실행 상태 표시 |
| 순간적인 설정 1로 재시도 제한 초기화 | 최근 5분에 최대 3회, 요청 간 최소 5초의 독립 예산. 성공/일시정지/프로세스 재시작으로 초기화하지 않고 SharedPreferences에 쓰기 전에 동기 보존. 실제 새 부팅에서는 초기화 |
| 오래된 owned 값으로 다른 사용자 세션 종료 | 기존 `owned`를 폐기. 자동 경로는 다른 Wi-Fi의 디버깅을 끄지 않음. 끄기는 사용자의 명시적 버튼에서만 수행 |
| 삭제한 클래스가 APK에 잔존 | 매 빌드마다 고유한 새 `android\build\run-<ID>` 사용. 기존 빌드 폴더에서 클래스를 수집하지 않음 |
| 다른 AVD 조작 가능 | 각 ADB 작업 전에 AVD 이름 `BlinkLink16`, 에뮬레이터 속성, 앱 패키지를 확인. 하나라도 다르면 작업 차단 |
| 업데이트 검사 오탐 | 실제 `install -r`, 전후 PID 변경, Activity 실행 전 foreground 서비스 시작, OFF→ON 복구를 검사 |
| 재부팅 검사 오탐 가능 | `/proc/sys/kernel/random/boot_id` 변경과 부팅 완료를 모두 요구. 처음에 위치 꺼짐/디버깅 0을 확인한 뒤 새 부팅에서 감시 시작과 복구를 분리 확인 |
| 외부 SDK 빌드의 키 경로 누락 | 키 생성 전에 부모 경로 생성. 별도 새 작업 폴더에 외부 SDK/JDK를 지정하여 빌드 확인 |

백그라운드 위치 권한이 없는 상태에서 자동 감시를 시작하는 것도 차단했다. 수동 복구 버튼은 등록 Wi-Fi에서 사용자가 직접 요청할 때만 실행하며 자동 요청 예산과 구분한다.

## 추가로 발견한 Android 동작

첫 수정본의 실제 강제 중지 검사에서 앱을 다시 열자 foreground 서비스가 다시 시작돼 실패했다. Android 15 이상은 중지 상태가 해제되면 BOOT_COMPLETED를 재전달한다. UI 표시만 고치는 것으로는 사용자의 중지 의도를 유지할 수 없었다.

`ApplicationExitInfo.REASON_USER_REQUESTED`의 이력을 확인하고, 사용자가 시작 버튼으로 해당 중지를 명시적으로 해제하기 전에는 부팅/업데이트 알림에서 서비스를 시작하지 않도록 보완했다. 최종 가상 기기 검사에서 강제 중지 후 다시 열어도 서비스가 없고 `감시 중단`으로 표시되며, 명시적인 다시 시작은 정상 동작했다.

원문: [Android 15 중지 상태 변경](https://developer.android.com/about/versions/15/behavior-changes-all#stopped-state), [ApplicationExitInfo](https://developer.android.com/reference/android/app/ApplicationExitInfo#REASON_USER_REQUESTED). 두 문서를 실제 열람했고 가상 기기의 exit-info에서도 FORCE STOP / USER REQUESTED를 확인했다.

## 검증 근거

- Java 정책 검사 10건, 새 재시도 예산 검사 14건 통과. 예산 검사는 순간적인 ON 이후 네 번째 요청 차단, 재직렬화/서비스 재시작, 경계 시각을 포함한다.
- Python 대상 보호 검사 3건 통과. 다른 AVD일 때 재부팅을 보내지 않고, 앱이 없을 때 설정 쓰기를 보내지 않음을 mock 호출 목록으로 확인했다. 다른 사용자의 가상 기기를 실제 변경하는 시험은 하지 않았다.
- 별도 새 작업 폴더 `work\android-build-review-project`에서 외부 SDK/JDK로 빌드와 새 키 생성 성공. 이전 `Probe$RemovedFeature.class`를 구형 출력 위치에 심어 놓아도 최종 DEX에는 포함되지 않는 것을 확인했다.
- 실제 가상 기기 실행 결과는 `work\android-lab\review-fix\runtime-results.json`, 재부팅 결과는 `reboot-results.json`에 저장한다. 결과 파일이 존재하고 해당 항목이 passed인 범위만 실행 완료로 본다.
- 에뮬레이터는 기존 전용 `BlinkLink16` / `emulator-5580`, Android 16 / API 36, WHPX, 화면 없는 실행을 사용했다. 모든 입력은 해당 게스트에만 전달했다.

최종 결과: **정책 10건 + 재시도 14건 + 대상 보호 3건 + 실제 가상 기기 13건 모두 통과**. 가상 기기 항목은 패키지 교체, 강제 중지 후 상태 표시, 명시적 재시작, 세 번째 요청, 네 번째 요청 차단, 프로세스 재시작 뒤 제한 유지, 수동 복구, 새 부팅/서비스/복구, Wi-Fi 재연결, 식별 불가 차단, 위치 복구, 일시정지, 외부에서 켠 값 유지다.

이번 조건에서 업데이트 후 네트워크 식별 복구는 29.5초, Wi-Fi 재연결은 4.6초였다. 재부팅부터 위치 설정 복구를 통한 최종 켜짐까지 59.4초였으며 순수 부팅 시간과 구분한다. 일반적인 실물 성능 보장은 아니다. 최종 부팅의 crash 버퍼는 비어 있었다.

최종 APK SHA-256: `1dc23fd9aa8897e65024b9b325e17925c9451ffa42b153473fa1d90e9905622b`. 앱 ID `kr.blinklabs.blinklink`, versionCode 2, versionName 0.1.1, minSdk 30, targetSdk 36을 APK에서 확인했다. 요약은 `work\android-lab\review-fix\summary.json`에 저장했다. 강제 중지 후 화면 PNG를 직접 확인했고 최종 화면도 `app\android\BlinkLink-0.1.1-preview.png`에 보존했다.

검사 후 이름을 다시 확인한 이 작업의 가상 기기만 정상 종료했다. 기존 PC 소스 변경과 VMware 기록 작업은 그대로 두었다. 에뮬레이터 회귀 스크립트는 준비된 앱 권한/등록 Wi-Fi/Android 네트워크 허용 및 새 부팅의 미사용 요청 예산을 전제로 실행한다. 연속 재실행으로 기존 요청 예산을 소모한 경우 먼저 전용 AVD를 재부팅해 시험 전제를 맞춰야 하며, 제품의 예산을 시험 편의를 위해 우회하거나 지우지 않았다.

첫 구현의 검사 결과는 [0.1.0 기록](VALIDATION-2026-11-11.md)에 남겼다. 당시 업데이트 검사는 자동 판정만으로 복구를 충분히 입증하지 못했으므로, 0.1.1의 실제 패키지 교체/프로세스 변경/설정 전환 검사가 이를 대체한다.

## 의미와 남은 범위

다른 Wi-Fi에서 자동 종료하지 않는 것은 의도적인 변경이다. Android의 전역 0/1 설정에는 현재 값을 누가 켰는지 알려주는 소유권이 없으므로 과거 기록으로 사용자 연결을 끊지 않는다. 등록 Wi-Fi 밖에서 새로 켜는 동작은 계속 차단한다.

S23 Ultra / One UI 8.5의 실제 절전, 무선 TLS, scrcpy 연결은 여전히 미검증이다. 가상 기기의 설정값 1이나 foreground 서비스 실행을 실물의 연결 성공으로 해석하지 않는다. 이번에도 호스트 GUI 입력·외부 업로드·파일 관리자 실행은 하지 않았다.
